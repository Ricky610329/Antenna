## ★ 探索型介入的評估法：效率 over 長 baseline,不做單批因果判決（2026-07-13,Ricky 修正）
- **癥結（Ricky）**：根稅（--root-cap）動的是**錨點抽樣分布**（擴散型介入,把探索攤到更多根系）,
  **不是瞄準帶外的定向槓桿**。期待它「第 N 批打穿帶外牆」＝把擴散介入當定向槓桿的類別錯誤;
  在現樣本量下把帶外紀錄歸因「根稅 vs 隨機」本質做不到。「甚至有沒有這因果關係」＝問得對,可能沒有。
- **正確評估框架**：擴散型探索介入（根稅/de novo/novelty/資訊臂…）**用探索效率評,不用單批命中/紀錄**:
  ①**gain-check L2 學習曲線**（邊際增益 b/N over 累積 HFSS 預算）——介入線 vs baseline 線比斜率;
  ②覆蓋度（根多樣性/新穎樣本佔比,analyze credit/data）;③**≥5 round 後才比**（擴散效應需長 baseline）。
- **鐵律（防過早判決,延伸「防過早悲觀/樂觀」）**：**不對擴散介入下 per-batch 因果判決**;
  各批只累積資料,紀錄照公證但不當「介入成功/失敗」的證據。R24 據此執行:根稅評估=多批後 L2 曲線對比。
- **可正當歸因的反例**：定向介入（如 O 臂 pred_oob 直接選帶外、H 臂劑量掃描）才可做較短視窗的因果判讀;
  擴散 vs 定向的分野=能不能指出「這批的好解是這個介入直接挑出來的」。

## 價值軸修正：過線後帶內餘裕邊際價值≈0,收益軸=帶外（2026-07-12,Ricky 定調）
- **定案（Ricky）**：「對 S11 與 Gain,只要過標之後額外的收益都沒有這麼重要了,壓低帶外才會帶來收益。」

- **不變**：「永不拿帶內換帶外」（2026-07-07）照舊——帶外只在過線者之間比;三標仍是硬閘。
- **保留（Claude 提,製造穩健性）**：可用解保留 **wm ≥ +0.15 buffer**（R11 公差:缺陷存活=margin 函數;
  +0.20 存活 56-72%、+0.03 級近全滅）——刀鋒王（如 o6_001 wm+0.00）當科學紀錄,不當製造候選。
- **生效範圍**：紀錄優先序即刻（帶外王=旗艦頭銜;margin/帶內紀錄降為參考點）;選批鍵 b4 起
  （pred_wm ≥ buffer → pred_oob 升冪主鍵）;R22 b3 判準已寫死照舊跑。gain 儀表補 oob 階梯。

**機制**：用 held-out 的 fresh HFSS 點量 SM 泛化，自調訓練量，取代固定 epoch / 逼 min_loss。
- 一輪 SM 訓練沿途存數個權重快照（採樣不同訓練量）→ 用「這一輪產生 pattern、剛過 HFSS 的 held-out 點」評快照
  → 「泛化 vs 訓練量」曲線的**形狀**給「加 / 減 / (學不動)」。
- **held-out 鐵律**：只能評「產生該點的那段（先前）訓練」的快照；**絕不可**評「正在對該點訓練」的快照
  （否則洩題 → 假結論『永遠多訓』）。
- **K=1 + EMA**：每輪一個 held-out 點就夠（配對比較抵消點難度），噪聲用 EMA 吸收、致動器慢走。

**旋鈕定案**：
- **ensemble 保持 5**（探測已與 ensemble 脫鉤，不必為省空間縮）；**訓練量探測只用 member0**（各成員同架構
  同資料、只差 init 擾動 → member0 的曲線代表全體）→ 快照只存 member0、~5 份/輪，與 ensemble 大小無關；ensemble(5) 負責 uncertainty。
- **判準＝配對 + 每桶 EMA + argmin**：同一 held-out 點上比各快照相對誤差（配對、抵消點難度）；各快照誤差
  按訓練量分桶、跨輪 EMA → 取平滑曲線 argmin 當目標訓練量（EMA 目標、慢走）。**護欄**：argmin 落快照範圍最外側
  → 用斜率方向把探測範圍外移/擴，別被固定範圍卡住。
- **快照 = ~5 份/輪、偏早密（log-ish 間距，knee 通常在早期）**。**存哪（實作定案，比原磁碟版更簡）：留記憶體**
  （`prev_snapshots` dict，每輪覆蓋上一輪）→ 零磁碟、零清理、resume 最多少一次 observation。member0 state_dict
  ~16MB×5≈80MB steady，可接受。（2026-07-02 實作時微調，取代原「存 `checkpoint/probe_snapshots/` + 滾動清理」。）
- **實作落點**：`sm_train.mode: adaptive`（新 mode）；`adaptive` 區段旋鈕 {snapshots, epoch_min, epoch_max, ema}；
  `AdaptiveSMTrainController` 在 `training.py`；快照/評估在 `surrogates.py`（`train_by_datas(snapshot_epochs=)` +
  `eval_snapshot`）；只探 member0。新追蹤訊號：`sm_train_epochs`/`probe_argmin`/`probe_min_err`/`probe_max_err`/`elite_n`。

**發車前健檢補記（2026-07-02，R4 派工前）**：
- **⚠ 歸因誠實**：`adaptive` 相對 `dlf` 其實換了**兩個機制**——除了 elite 訓練量 1→自適應，**也拿掉了對最新點
  的 `train_one_data` 激進單筆擬合**（單筆擬合＝已確認反模式；最新點反正在 elite 裡照訓）。R4 vs R3 的差異
  歸因要講「SM 更新規則整包換」，不能只說「訓練量自適應」。
- **死鎖修復（模擬實證）**：原控制器早期雜訊把 target 壓到 ≤5 後永遠救不回（整輪默默退化回 dlf）。成因×2：
  整數 target 上做 EMA、1.3× 加碼被 round() 吃掉（低訓練量吸收態）；argmin 在歷史所有桶選、範圍外的過期低值
  永遠投票。修法：**target 內部存 float**（對外才取整）＋ **argmin 只在本輪有觀測到的桶裡選**（bucket EMA 只
  平滑值）。修後三情境驗證：死鎖恢復、sweet spot 收斂、純雜訊保守退低（＝dlf 現狀＝安全失效；監測法：
  `probe_min_err≈probe_max_err`＝曲線平＝探測沒資訊）。
- **斷點續跑**：控制器狀態只在記憶體 → 重啟歸零重學；`seed_target()` 用 metrics.csv 最後一筆 `sm_train_epochs`
  續 target（bucket 重學即可）。HFSS 當機重啟頻繁，沒這個 500-epoch run 的自適應會一直被打斷。

依據＝diffsim session（analysis-08/09）的實測價值差——四支 agent 推翻了**三個已寫進日誌的結論**，
而我自己寫的 13 條測試對遠場**零覆蓋**（注入 4 個嚴重 bug，一個都沒抓到）。

| 觸發點 | 派什麼 | 該輪實績 |
|---|---|---|
| **改完物理/核心模組** | 用**新學到的 bug 型態**回頭查舊模組 | 抓到 L1 二值域梯度 100% NaN（舊測試用鬆弛值，永遠測不到） |
| **報數前（gate/紀錄/換王）** | 對抗式驗證 ＋ 靜默失效獵人 | 抓到 `build_l2` 修正沒落地、pooled ρ 的「免費分數」污染 |
| **卡住 >2 小時** | 文獻/外部實作對照 | 推翻「缺自由空間鏡像」的因果——實際是**多了 15× 偽損耗**，方向完全相反 |
| **收檔前** | 專案衛生（死碼/文件漂移/資料紀律） | 揪出 `verify_interp` 與 `verify_disc2` 檔名全同 → round-10 §63 證據污染 |

**三條執行紀律**（都是這輪踩過才寫的）：

1. **報數前的驗證要「等它回來再報數」**。這輪是**同時**派驗證與跑 gate，結果驗證晚回
   → 報數作廢 → 重跑選參 → 重跑 gate，整輪重做。判準本來就寫了「驗證不過報數無效」，
   **是執行時沒守**，不是規則要改。
2. **brief 必須帶「已知的失效模式」**。效果最好的靜默失效獵人，是因為我在 brief 裡列了
   **自己已經踩過的三次**當 pattern，它就去找同類、又找到三個。純講「檢查有沒有 bug」效果差很多——
   **agent 的價值來自我給的 prior，不只是它的獨立性**。
3. **agent 的結論不當判決**。這輪 agent 也報過錯（把 `η₀` 的位置說反、把 CI 讀成顯著）；
   凡影響方向的宣稱**自己重跑一次**再採信。與 `/reconcile` 的精神一致。

**適用範圍**：批次線的 `/batch-cycle`／`/notarize` 已有公證鐵則覆蓋「報數前」這格；
本節主要補的是**開發/分析型工作**（analysis-NN、新模組、重構）——那條線原本只有我自己檢查自己。

**追加:平行分析 fanout 五則（2026-08-06 回顧輪;analysis-11/回溯驗證/系統回顧三役實證）**：
①拆軸互斥（每個 agent 一條獨立軸,brief 裡寫明別人的地盤）②判準寫死在 brief（通過線先於結果）

## 驗收指標要用「使用方式」的指標，不是「看起來合理」的指標（2026-08-03，diffsim 實例）

- **事件**：diffsim 全程（analysis-08/09/10）用**層內 rank ρ** 當 gate。收檔後才實測
  「翻譯成選批（top-K）效益」——結果**反向**：全域 ρ **+0.433** 的 L3 在 K=30 選批
  只有 **30%** 機率勝過隨機；全域 ρ 僅 **+0.078** 的影子 CNN 反而有 **71%**。
  ⇒ 依 ρ 下的建議（「L3 當新域冷啟動排序器」）**收檔 20 分鐘後就撤回**。
- **原則**：訂 gate 前先問「這個模型將來**怎麼被用**」，再挑指標。
  選批用 top-K 命中率／等效預算倍率；連續控制用誤差；排序展示才用全域 ρ。
- **這不是新知識**（Lambert L4DC 2020 的 objective mismatch，analysis-08 §文獻節已引），
  **是知道了還照樣犯**——所以寫成規則而不是提醒。
- ★★ **後續補上的縱向證據（比橫向比較強得多）**：修掉一個**真正的物理 bug**
  （饋電模型用 0.2mm 死端代表 22.5mm 傳輸線），gate 指標 ρ 改善 **+124%**
  （dev：+0.194 → +0.434，配對 B=3000，P=100%），而**選批的 P(勝隨機) 從 18% → 17%
  ——完全沒動**（analysis-10 §7.2）。
  ⇒ 兩個指標不只「不等價」，在這問題上**幾乎正交**：全域 ρ 量的是**整體順序**，
  選批只取決於**分布頂端那幾十筆的相對位置**。把中後段排得更對，對前者貢獻很大、對後者毫無貢獻。
  ⇒ 我當時據此推論「任何改善 held-out 誤差／前瞻 ρ 的工作都不能預設會改善選批」，
  並建議批次線查五軸 KPI ①。**★ 已查，該推論不成立，撤回**（analysis-10 §8）：
  拿 `sm_reanchor` v50–v100 十三個版本在同一批 OOS 樣本上逐版量，
  **ρ vs P(勝隨機) = +0.720、ρ vs top10% 命中率 = +0.775、|err| vs 命中率 = −0.664**
  ⇒ **五軸 KPI ① 是有效的代理**，重錨把 SM 訓準，選批能力確實跟著上去。
- ★ **真正的分界不是「哪個指標」，是「改善的性質」**：
  | 改善的性質 | 例 | ρ 能當代理嗎 |
  |---|---|---|
  | **全域均勻** | 加資料、調容量、修訓練 bug（SM 的情形） | ✅ 可以 |
  | **結構性** | 修某一項物理、加某一個特徵、換某一層（diffsim 的情形） | ❌ **必須直接量 top-K** |
  ⇒ 落地規則：**改動只碰模型的一部分機制時，ρ 不夠，要補 top-K。**
- ⭐ **同一批實驗的副產品（對批次線直接有用）**：**主 SM（mlp）在完全未見過的域選批
  比隨機還差**（P(勝隨機) = 21–26%，K=30/60 都是）。開新域時**不要用主 SM 挑候選**。
  影子 CNN 與 L1 至少不害。相關：R50 雙外軸產線正在開新域。
