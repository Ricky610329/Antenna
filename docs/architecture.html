⚠ 命名陷阱（先看這個，否則整份都會理解錯）

論文與程式碼的「GEN」同名、角色卻相反：

  • 論文的 GEN = Gradient Estimation Network（梯度估計網路）= 代理模型（程式碼 OldSM / HFSSNet）。它當不可微分 HFSS 的「可微替身、提供梯度」，故名「梯度估計」。
  • 程式碼的 SigmoidGEN = 生成器 G（目標響應→pattern）。它名字裡的 GEN 只是 Generator 的縮寫，不是論文的 GEN。

因此本檔一律：生成器 G（藍）＝SigmoidGEN；代理模型（論文 GEN）（綠）＝OldSM/HFSSNet。

1核心概念：三個角色 + 一條閉迴路

傳統流程是「先畫結構 → 丟 HFSS → 看響應」。本專案反過來：先指定目標響應（如 28 GHz 處 S11 要凹、Gain 要高），再讓網路生成達成它的 25×25 二元金屬 pattern。三個角色：

G生成器

目標響應 → pattern

程式碼 SigmoidGEN。MLP 把目標響應映成 logits，再用 STE 可微分二值化輸出 0/1 圖樣。是「要被訓練」的對象（論文的 G）。

GEN代理模型

pattern → 預測響應

程式碼 OldSM（內部 HFSSNet）。論文稱此為 GEN（Gradient Estimation Network）。一個「可微分、毫秒級」的網路，當不可微分 HFSS 的替身，讓 G 的梯度能借道反傳。

SIM模擬器

pattern → 真實響應

SinglePortSimulator/DualPortSimulator。透過 COM 驅動 Ansys HFSS 做真正電磁模擬，慢但準確，是 ground truth。

為什麼需要「代理模型（論文 GEN）」？

  • HFSS 不可微分：無法對它 backward() 取梯度 → 生成器 G 沒辦法直接靠它訓練。
  • HFSS 很慢：每次模擬要數分鐘。
  • 於是引入代理模型當「可微分替身」：G→pattern→代理→loss 可反傳更新 G；每跑一次真實 HFSS，就用 (pattern, 真實響應) 線上訓練代理，讓它在「G 當前常產生的圖樣」附近越來越貼近真實。論文稱這個替身為 GEN。

閉迴路資料流

藍虛線＝梯度反傳（更新 G）；綠虛線＝用真實資料線上訓練代理（論文 GEN）；實線＝前向流。HFSS 不可微，故 G 借道代理取得梯度。

2每個 epoch 的流程（A–G）

早停 / 回滾判斷：若 real_loss 連續 patience 次沒進步 → 回滾 G 到歷史最佳 epoch，並重訓代理。代理★ 這是獨立於 ACP 的機制，見第 3 節
生成 pattern：G 依目標響應生成 pattern，疊上固定饋電金屬塊（single 疊 lower；dual 疊 upper+lower）。G
去重：若這張 pattern 先前模擬過 → 直接取快取結果（jump），省下昂貴的 HFSS。
真實模擬：跑 HFSS 得真實響應與 real_loss，並用這筆真實資料線上訓練代理。SIM代理
更新歷史最佳：維護 min_loss / best_epoch。
更新 G：pattern 經代理得預測響應，算 loss（= 響應誤差 + pattern 正則化）→ backward() → step()。G代理
存檔 / 繪圖 / 記錄：寫入 TEMP（Record），支援斷點續跑。
pattern 正則化（可製造性約束）：論文主方法是 SC Loss（SpectralConnectivityLoss，圖譜連通度）；其餘 total_variation_loss、island_suppression_loss(≈論文 KNS Loss)、GapClosingLoss 多為對照基準。FeedReachability（R_feed）是評估指標、非訓練 loss。

3論文核心機制與術語對照

論文（吳維文碩論）在線上反向設計框架上，用三個機制解決前人三大缺陷：

前人缺陷論文機制程式碼
收斂卡局部最小ACP（自適應循環策略 / Adaptive Cyclical Policy）AdaptiveCyclicalScheduler
金屬孤島不連通SC Loss（圖譜連通度，Fiedler 值 1/λ₂）SpectralConnectivityLoss
冷啟動樣本效率低DLF（動態損失過濾）+ Warm Start（物理初始解）online_dataset 篩選 + 疊 lower/upper
★ ACP 與 rollback（回滾）是兩個獨立機制 — 不要混為一談
  • ACP（AdaptiveCyclicalScheduler）只含「主動式高原偵測 + 自適應重啟 + lr/tau 雙耦合退火」——只動學習率 lr 與溫度 tau，不碰權重。論文第 3.2 節通篇無「回滾」。
  • rollback（載回歷史最佳 epoch + 重訓代理）是主迴圈層級的獨立動作（train_single.py 主迴圈）。ACP 只提供「停滯訊號」。
  • 兩者用各自獨立的 patience 計數器：rollback 用主迴圈的 TEMP.early_stop('real_loss', config['patience']=10)；ACP 內部另有一套 patience（只重啟 lr/tau）。
tau（溫度）的角色：lr 與 tau 由 ACP 同步退火——暖身期高溫（輸出平滑、廣域探索）→ 退火期低溫（輸出趨近乾淨 0/1、可製造、收斂定形）。tau 控制 AntennaPattern.binarization 的 STE 軟硬程度。
疑似落差（待確認）：論文 DLF 是「每輪用累計平均重新過濾整個 buffer、汰除舊次佳樣本」；但 train_single.py 目前只做「real_loss < 平均才寫入」——這是論文點名批判的對照基準，非 DLF 本體。（train_dual 的 rollback 有 filter(upper=avg)，較接近。）

5關鍵資料抽象

AntennaPattern

G 輸出的像素圖樣包裝。merge()（多塊疊合）、binarization()（STE 可微分二值化，tau 控制軟硬）、simulate()、series（攤平餵代理）、+ 疊饋電塊、~ 取 detach 版做去重。

AntennaResponse 家族

TargetResponse 設計目標曲線+綁 loss hook；MultiResponses 包多條 S 參數；criterion() 依註冊 loss 算「響應 vs 目標」，是 G→代理 反傳鏈的末端。

Record（TEMP）

逐 epoch 時序記錄器：early_stop（觸發回滾）、find（反查最佳 epoch）、index（pattern 去重）、save/load（斷點續跑）。app.py 依賴其序列化格式。
