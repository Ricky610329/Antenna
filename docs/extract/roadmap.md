# 建置路線圖：從現在到新系統

> 對應設計見 [`architecture-draft.md`](architecture-draft.md)。
> **排序原則**：**先用零成本的方式驗證未知，再蓋昂貴的東西**。
> 架構草案裡有三條標 `❓` 的假設，其中兩條可以在**不寫任何新系統程式碼**的前提下驗證——
> 那兩條先做，因為它們的答案會改變架構。

---

## 階段 A　零成本驗證（不蓋東西，先解掉架構的問號）

用既有資料與既有機器，驗證三條會影響架構的假設。**全部零模擬機時**。

### A-1　換模型／harness 重跑同一輪（驗 C-11「弱模型化」）

**為什麼先做**：架構草案 §8.2 的整個代理層設計建立在「判定已下沉到程式，換模型會得到同一份帳」
之上。而原專案自陳**這是設計意圖、沒做過對照實驗**。若這條不成立，L5 的分工要重畫。

**做法**：選 2–3 個已收檔且已判讀的歷史批 → 快照 → **遮蔽原判讀** → 讓另一個模型或另一個 harness
從接手流程開始跑同一份判讀與記帳 → 比對三層：

| 層 | 預期 | 若不符代表 |
|---|---|---|
| 判定層（工具印出的「→ 行動」被執行的結果） | 一致 | 判定沒真的下沉，還在模型腦裡 |
| 記帳層（該寫的數字、是否觸發驗證/停批） | 一致 | 流程文件有歧義分支 |
| 提問層（下一步假設、要不要開新輪） | **不一致** | 若也一致，反而說明代理沒在提問（更壞） |

**成本**：半天。**產出**：C-11 從「未驗證」變成有數字；同時檢驗本卷宗夠不夠讓別人接手。

### A-2　分層量「勝過隨機的機率」（驗「重訓＝跟上分布」）

**為什麼**：架構草案主張「重訓的價值不是讓模型更準，是讓它跟上搜尋走到的地方」。
這是從 C-07（域外崩潰 21–26%）與 C-08（相關性改善不轉化）推出的**解釋**，不是實驗結果。
它決定重訓策略（近期資料加權 vs 全量重訓）。

**做法**：用既有的稽核工具，把候選池按「距離當前搜尋區域的遠近」分層，
分別量勝過隨機的機率。若「近層高、遠層低」且差距隨時間拉大 → 假設成立。

**成本**：數小時，純離線。

### A-3　盤點「取樣政策 × 變異規則」分類法

從 `select_*` 那 60+ 個實例裡挖出完整清單（不搬程式碼，只要分類）。
**產出**：策略層的詞彙表——新系統的策略要能表達這些，才算沒退步。

**階段 A 的退出條件**：三份結果寫回 [`claims.md`](claims.md)／[`open.md`](open.md)，
架構草案的 `❓` 標記更新。**A 沒做完不要開始蓋 B。**

## 階段 B　最小骨架（L0 + L1 + L3，單策略）

目標：證明**分層切得對**，用最小的東西跑通一整條路。

**範圍**：
- L0 資料層：條目四欄位（幾何宣告／量測條件／響應／世代）、內容 hash 去重、協調原語三件套
- L1 執行層：佇列 + 原子認領 + 心跳 + 容錯（照搬，見 [`assets.md`](assets.md) §一）
- L3 判準層：`Spec` 物件（量測口徑凍結／評分層可換）
- **只跑一個策略**（等價於現行的補池路徑）

**驗收**：能重現現有的一個歷史批——同一份輸入、同一組設定，跑出**逐筆相同**的結果。
這是最強的「行為不變」證明。

⚠ **前置**：現行的執行函式**沒有任何測試**（見 `assets.md` §四）。抽取前必須先補特徵化測試
（用假模擬器驅動，斷言結果檔的鍵與值），否則沒有「行為不變」的定義。這一步約佔本階段 1/3 工時，
不可省——那是三台機器的命脈。

**風險**：中高。**退路**：舊系統完全不動，新骨架跑不通就繼續用舊的。

## 階段 C　策略層（架構的主要新增，也是唯一無實作證據的一層）

**為什麼要早做**：架構草案 §5 全部是設計推論。原專案只跑過「一條批次線 + 一條背景填充 +
一條無人值守迴圈」，**從沒跑過 N 個獨立策略並行**。這層若不成立，整個架構要重想。

**範圍**：
- 策略 = 取樣政策 + 變異規則 + 節奏，做成可註冊的物件
- 2–3 個策略並行、共享資料庫、各自節奏（**非同步但共享狀態**）
- **每個策略常駐自帶 blind 對照臂，比例不得為 0**
- 策略 lifecycle：誰決定生死、憑什麼指標

**驗收**（這是本階段的重點，決定架構成不成立）：
1. 能**分別**算出每個策略的「勝過隨機」比值——多策略下歸因仍然可行
2. 資料庫共享確實有效：策略 X 能用到策略 Y 剛產出的結果（用時間戳驗）
3. 多樣性不靠單一策略內的稅也能維持（量策略池產出的互距分布，對照舊系統）

**若驗收失敗的退路**：退回「一條主線 + 背景填充」的舊形態（已證明可行），
把策略多樣性改成「輪次之間切換」而非「同時並行」。

## 階段 D　新域驗證：冷啟動協議（「任意 spec」的前提）

**為什麼這是里程碑而不是 NL 介面**：代理模型在沒見過的域選批**比亂猜還差**（C-07）。
每個新 spec 都會撞上這個。解析與產檔反而最容易——牆在這裡。

**做法**：拿一個新元件類型當新域，跑通完整協議：

```
第 1 批   強制 blind（模型不得參與挑選）
累積      到樣本數門檻
上崗閘    排序相關性 + 命中率統計檢定
上崗後    用「勝過隨機的機率」驗收，不是相關係數
```

**驗收**：新域的模型上崗後「勝過隨機 > 50%」，且**上崗前後的成本曲線**有記錄
（回答「新 spec 要燒多少機時才能讓模型有用」——這是新系統對外最有價值的一個數字）。

**跑不通的話**：「任意 spec」這個目標要降級成「同一問題族內換規格」（那條已被驗證：
規格改版不重量、缺口 6.1→3.05）。

## 階段 E　代理層與 harness 中立

**範圍**：
- 收檔偵測寫成獨立 CLI（blocking + 退出碼），終態寫**事件檔**
- 消費端可以是任何 harness 的背景監看／cron／輪詢／人 → 喚醒源從「唯一硬綁定」降級
- 流程文件（runbook）與判定工具分離：判定在程式、runbook 只描述分支
- 記憶/脈絡以 repo 內檔案為正本，不依賴 harness 的自動載入

**驗收**：A-1 的對照實驗在**新 harness 上重跑一次**仍然通過。

## 依賴與並行

```
A-1 ─┐
A-2 ─┼─→ 架構草案的 ❓ 更新 ─→ B ─→ C ─→ D
A-3 ─┘                              └─→ E（可與 C/D 並行）
```

- **A 三項可完全並行**，且都是零機時
- B 必須等 A（A 的結果會改架構）
- C 必須等 B（需要 L0/L1 骨架）
- E 可與 C/D 並行（不碰搜尋邏輯）

## 全程硬規則

- 舊 repo 的既有測試必須維持全綠（含基準零漂移）；跑測試要釘住執行緒數（見 [`incidents.md`](incidents.md) I-11）
- 任何碰執行器的改動：一台先驗、綠了才全部部署（I-10）
- 量測資料只增不減，備份用增量、只讀、零刪除（架構草案 §2.5）
- 每個階段的結論寫回 [`claims.md`](claims.md)，含**失敗的那些**（負結果是一等產物）
