⚠ 一句話前提：梯度只走 SM，真值只走 SIM

G（生成器）被訓練要靠梯度，但 HFSS 不可微 → 梯度走 G → pattern → SM（可微替身）→ GEN loss → backward。 真實 HFSS 的 sim_loss 不回傳到 G，它只拿來：(a) 餵 ACP 當「卡住了沒」的訊號、(b) 觸發 rollback、(c) 線上監督 SM。把這兩條分清楚，整份圖就懂了。

2Loss 結構：一個 GEN loss（回傳 G）＋ 一個 sim_loss（不回傳）

2.1 GEN loss — 唯一會 backward() 到 G 的東西 可微

# training.py:316-323 —— 全部可微，loss.backward() 只更新 G loss = response.criterion() # ① 主損失：SM 預測響應 vs 目標 + output_element.total_variation_loss(tv_w) # ② 抑制破碎 + output_element.island_suppression_loss(is_w) # ③ 抑制孤島 + sc_w * sc.forward(...) # ④ 全域連通（Fiedler 1/λ₂） + gap_w * gc.forward(...) # ⑤ 補細縫（形態學閉運算）

2.2 sim_loss — 真實 HFSS，不回傳 G 不可微/不回傳

# training.py:289-295 result = output_element.simulate() # SIM：真實 HFSS 響應（no_grad） sim_loss = result.criterion() # 真實響應 vs 目標（同一組 loss hook） smodel.train_one_data(series, stack) # 用真值線上訓練 SM

sim_loss 是「這張 pattern 真的好不好」的 ground truth。它有三個去處，沒有一個是 backward 到 G：

  • 餵 ACP：generator.step(scheduler_param=sim_loss) — ACP 看它判斷「卡住了沒」。
  • 觸發 rollback：state.early_stop("sim_loss", patience) 連續沒進步 → 回滾 G 到最佳 epoch + 整批重訓 SM。
  • 監督 SM ＋ 篩好樣本：train_one_data 線上微調 SM；低於平均的存進 online 好樣本庫。
為什麼要兩個 loss？ 因為 G 只能用「可微的近似」（SM）算梯度，但 SM 自己會飄；所以再用「真實但不可微」的 sim_loss 當北極星，去校正 SM、並在 SM 把 G 帶歪時把 G 拉回（rollback）。這就是 online learning 閉迴路的本質。

3ACP 怎麼弄：一個排程器，同步管 lr 與 tau

ACP＝AdaptiveCyclicalScheduler（論文核心機制）。它不是普通 lr scheduler — 它同時吐兩個東西回主迴圈：給 optimizer 的 lr 和給 STE 二值化的 tau（溫度），兩者一起退火。

ACP 旋鈕（YAML scheduler:）意思預設
T_0 / T_mult週期長度 / 每次重啟後週期倍率（warm restart）100 / 1
lr_min · temp_max · temp_minlr 下限、tau 上/下限（lr 高點＝cfg.lr）1e-6 · 4.0 · 0.1
on_plateaulinear｜peak：sim_loss 卡住時，週期高點怎麼衰減linear
patience · factor連續幾次沒進步算 plateau、衰減乘數25 · 0.7
warmup_ratio每週期前段暖身比例0.2
ACP vs rollback 是兩件事（別混）：
  • ACP＝連續調節：每個 epoch 依週期 + plateau 給新的 lr / tau（generator.step 內）。
  • rollback＝離散急救：sim_loss 連續 patience 次沒進步 → 把 G 載回最佳 epoch、用 online 樣本整批重訓 SM。它讀 sim_loss，但機制獨立於 ACP（對齊論文：rollback 不歸 ACP 管）。
